# 今日任务总结（2026-03-22）

## 任务目标
在不改变业务功能、业务逻辑、用户流程、接口语义、路由语义和页面视觉的前提下，对小程序进行无痕性能优化，提升冷启动、页面切换、滚动与交互流畅度。

## 诊断结论
1. 主包过重：优化前 `pages.json` 中 20 个页面均在主包，冷启动注入压力较大。
2. 分包缺失：无 `subPackages`，低频深层页与首页竞争启动资源。
3. 列表渲染风险：多处 `v-for` 使用索引 key，存在复用与重排成本。
4. 图片加载压力：多页面列表图未懒加载，滚动期主线程压力偏高。
5. 生命周期重复负载：个别高频页面首次进入存在重复初始化/重复请求风险。
6. 响应式减负空间：存在 deep watch 场景可安全收敛依赖追踪范围。

## 已实施的无痕优化

### 1) 配置层与分包层
- 在 `src/pages.json` 启用：
  - `lazyCodeLoading: "requiredComponents"`
  - `subPackages`（将低频深层页下沉分包）
  - `preloadRule`（仅配置克制的关键链路预下载）
- 结果：主包页面 `20 -> 6`，分包 `0 -> 12`，总路由集合保持一致。

### 2) 模板渲染层
- 全局修复高风险列表 key：将 `:key="index/idx"` 收敛为稳定唯一 key（如 id 或稳定组合键）。
- 目的：降低列表 diff 抖动与不必要重渲染。

### 3) 图片与资源加载层
- 在长列表/非首屏图片场景新增 `:lazy-load="true"`（共 11 处）。
- 目的：减少首屏解码和滚动并发压力。

### 4) 生命周期与执行时机
- 对高频页面做最小侵入修正：
  - 避免首进时 `onLoad + onShow` 重复执行重任务。
  - 安全并行无依赖请求（`Promise.all`）以降低首屏阻塞时长。

### 5) 响应式系统减负
- 收敛 deep watch：由追踪整对象改为追踪必要字段（如 `dish.id`）。
- 目的：降低依赖收集与无效触发。

# PUA Debugging Protocol
## ⚠️ 启用条件
当遇到以下情况时自动激活或应用户 `/pua` 请求激活：
- 连续两次修复尝试失败
- 出现「未知错误」或模糊的异常栈
- 环境启动失败、接口调用不通、构建报错

## 🔍 排查铁律 (Ironclad Rules)
1. **绝不瞎猜**：停止一切「可能是因为...」的猜测代码修改。必须通过查看日志、增加打印断点、检查网络请求响应真实数据来确认问题。
2. **追根溯源**：查网络问题必须看抓包（URL/Method/Status/Payload/Response），查空指针必须加防御性代码打印哪个对象为空。
3. **闭环思考**：报错 -> 取证 -> 假设 -> 验证假设 -> 实施修复 -> 二次取证验证。
4. **拒绝甩锅**：绝对不允许回复“请您自己检查一下XX配置”，必须由我自己寻找并检查。
5. **本地查证**：如果缺少日志，优先添加详细日志并重新运行/请求，而不是直接盲改代码。

## 🎯 具体执行
- **前端排错**：审查响应 JSON，确认数据结构是否匹配 Vue/Uniapp 组件的期望；使用 nullish coalescing/防御性判断避免 Cannot read properties of null。
- **后端排错**：审查 Controller 输入输出，利用 `view_file` 或 `grep_search` 查看实际的 Error Stack 追踪，验证数据库实际结构，不要想当然。

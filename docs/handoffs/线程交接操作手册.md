# 线程交接操作手册
## Shell 与编码
- 首次使用 shell 前，先执行：`[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`
- 所有读取文件的命令显式使用 UTF-8；运行命令、写入文件、生成提交信息时，也优先使用 UTF-8 安全写法，避免乱码。
- 所有新增或修改的文件，统一保存为 UTF-8（无 BOM）。
- 严禁使用 GBK、ANSI 等本地编码；严禁提交包含乱码、问号替代字符或不可读字符的内容。
- 在 Windows PowerShell 5.1 中，避免使用可能写出 BOM 或受系统本地编码影响的写法。
- 一旦发现乱码或文件不是 UTF-8（无 BOM），先修正编码或命令写法，再继续后续操作。

## 目的
在多线程协作中保证信息不断档，避免重复排查、重复返工。

## 硬规则（必须执行）
1. 没写交接文档，不能结束线程。
2. 每个线程结束时，必须复制 `docs/handoffs/TEMPLATE.md` 新建一份交接文档。
3. 交接文档文件名必须使用：`YYYY-MM-DD_HHMM_short-topic.md`。
4. 交接完成后，必须在 `docs/THREAD_HANDOFF.md` 顶部追加最新交接文件。

## 新线程启动第一步固定动作
1. 先读 `THREAD_HANDOFF.md`。
2. 再读最新 1-2 份 handoff 文档（位于 `docs/handoffs/`）。
3. 然后执行二次确认：
   - `git status`
   - `git diff`

## 线程结束标准流程（Checklist）
1. 完成本线程改动与验证。
2. 复制模板文件：
   - `docs/handoffs/TEMPLATE.md`
3. 按命名规范保存为新文件：
   - `docs/handoffs/YYYY-MM-DD_HHMM_short-topic.md`
4. 填写完整交接内容（目标、改动文件、根因、验证、风险、下一步）。
5. 更新 `docs/THREAD_HANDOFF.md`（新增最新交接文件索引）。
6. 自检无遗漏后再结束线程。

## 推荐最少记录内容
1. 本线程目标和范围。
2. 改动文件清单（精确到路径）。
3. 根因和证据。
4. 验证命令与结果。
5. 未完成项与风险。
6. 下一线程第一步建议。

## 快速命令参考
```bash
git status
git diff --name-only
```

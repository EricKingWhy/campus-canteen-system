# ECC Bug 修复专用 Prompt（排错 + 热修复）

## 0. 一键总控

```text
按 ECC 的 Bug 修复流程处理这个问题：{Bug 描述}。
要求：先复现、再定位、再修复、再回归、最后输出 RCA（根因分析）。
```

## 1. 快速定位（6 条）

```text
当前现象：{现象}。请先列出最可能的 5 个根因，并设计最小验证步骤。
```

```text
我只要“最快定位路径”：请按优先级给我排查顺序和每一步预期结果。
```

```text
根据报错日志 {日志片段}，推断问题发生层：前端/接口/服务/数据库/缓存。
```

```text
请从最近改动中定位可疑点：{提交信息或文件范围}，并给出复现方案。
```

```text
帮我生成复现脚本或复现步骤，目标是 100% 稳定复现这个问题：{Bug 描述}。
```

```text
先不要修代码，先确认根因证据链：现象 -> 触发条件 -> 数据状态 -> 根因。
```

## 2. 修复实施（6 条）

```text
以最小改动修复 {问题}，并说明为什么这个改动最安全。
```

```text
请先写一个失败测试覆盖该 Bug，再给出通过测试的最小实现。
```

```text
对 {问题} 给两套方案：快速热修复方案 + 长期治理方案，并对比风险。
```

```text
修复 {问题} 时请保留向后兼容，不能影响 {关键流程}。
```

```text
对修复点添加必要日志/监控埋点，方便后续追踪同类问题。
```

```text
修复后请给我“受影响模块清单”和“可能连带风险”。
```

## 3. 回归验证（5 条）

```text
请为本次 Bug 修复生成回归测试清单，按高风险优先级排序。
```

```text
验证这个修复不会影响 {功能A/B/C}，给我可执行的检查步骤。
```

```text
输出修复验收标准：功能正确、性能不退化、安全不降低。
```

```text
请补充 3 条边界测试和 2 条异常路径测试，避免同类问题复发。
```

```text
请给上线建议：是否可热修复立即上线，若否请说明阻塞项。
```

## 4. 线上故障专用（4 条）

```text
线上故障：{描述}。先止血再修复，给出 30 分钟内可执行应急动作。
```

```text
请给我应急预案：降级、熔断、开关控制、回滚，按优先级排序。
```

```text
生成本次事故复盘模板：时间线、影响范围、根因、改进项、Owner。
```

```text
请输出“可回滚版本”与“回滚触发条件”，保证上线安全。
```

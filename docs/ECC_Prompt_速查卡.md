# ECC Prompt 速查卡（24 条一键可用）

适用：你已经安装 ECC，希望直接复制 Prompt 就开干。  
用法：把 `{}` 内内容替换成你的项目信息。

## 1. 通用总控（4 条）

```text
按 ECC 标准流程处理这个任务：{任务描述}。先规划，再 TDD 实现，再代码评审，再安全评审，最后给我收尾清单。
```

```text
按生产级标准完成：{需求}。要求可维护、可测试、可回滚，并输出风险说明。
```

```text
先不要直接改代码。先做技术方案评估：目标、边界、依赖、风险、实施步骤，然后再开始实现。
```

```text
请以“可直接执行”为目标输出：1) 分步计划 2) 代码改动 3) 验证结果 4) 回滚方案。
```

## 2. 新功能开发（5 条）

```text
新增功能：{功能名}。按 planner -> tdd-guide -> code-reviewer -> security-reviewer 流程执行。
```

```text
请先写失败测试再实现 {功能名}，并给出关键边界测试点。
```

```text
实现 {功能名}，要求：小步提交、每步可验证、最终给出影响范围。
```

```text
帮我做一个最小可用版本（MVP）实现 {功能}，并列出后续增强路线图。
```

```text
在不破坏现有行为前提下实现 {功能}，请明确兼容策略和迁移策略。
```

## 3. Bug 修复（5 条）

```text
修复 Bug：{现象}。先复现再定位再修复，最后输出根因分析（RCA）。
```

```text
对 {报错信息} 做排查：先给出 3-5 个最可能根因，再逐一验证并修复。
```

```text
为这个 Bug 补一条回归测试，确保后续不会再发生：{Bug 描述}。
```

```text
请优先最小改动修复 {问题}，并说明为什么这个改动风险最小。
```

```text
我需要热修复方案：{线上问题}。给我快速修复路径 + 稳妥修复路径，两套方案对比。
```

## 4. 代码评审与安全（4 条）

```text
review 当前改动，优先找：逻辑 bug、行为回归、缺失测试、边界条件漏洞。
```

```text
对 {模块} 做安全审查：输入校验、鉴权、注入、敏感信息、错误泄露。
```

```text
请按严重级别输出评审问题（Critical/High/Medium/Low）并给修复优先级。
```

```text
给我一个“可上线/不可上线”的结论，并列出阻塞项。
```

## 5. 重构与性能（3 条）

```text
重构 {模块}：保持行为不变，提升可读性和可测试性，最后给前后对比。
```

```text
排查 {慢接口/慢页面} 性能瓶颈，给出测量数据、根因和优化方案。
```

```text
把这段复杂逻辑拆成小函数并补测试：{文件路径/函数名}。
```

## 6. 前后端联调（3 条）

```text
帮我梳理 {页面} 与 {接口} 的联调清单：请求参数、返回结构、异常分支、空态处理。
```

```text
请生成这个接口的 mock 数据和联调校验步骤：{接口名}。
```

```text
定位前后端字段不一致问题：{字段说明}，并输出统一契约建议。
```

## 7. 发布与回归（3 条）

```text
给我本次改动的回归测试清单，按高风险优先排序。
```

```text
为 {版本功能} 生成上线检查单：配置、数据库、依赖、监控、回滚。
```

```text
请输出这次发布说明：用户可见变化、技术变更、风险提示、回滚步骤。
```

---

建议：把最常用的 5 条 Prompt 复制到你常用输入法短语库，效率会非常高。

# 2026-01-25 开发日志：用户管理模块深度修复

## 📅 今日目标
修复管理端「用户管理」页面无数据、操作失败及登录 404 问题，打通前后端数据链路。

## 🛠️ 修复内容详细记录

### 1. 后端类加载问题 (AdminUserController)
*   **现象**：后端启动无 `/admin/users` 映射日志，前端 404，但 `.class` 文件存在。
*   **根因**：IDEA 编译缓存与 Maven target 不一致，导致新写的 Controller 未被加载。
*   **修复**：执行 `Invalidate Caches` 并重新编译，验证接口 `/admin/users` 返回 401 (证明存在)。

### 2. 前端代理与路径重写 (Vite Proxy)
*   **现象**：登录和已存在的管理端接口全部 404。
*   **根因**：`vite.config.ts` 中的 `rewrite` 规则错误地将 `/api` 替换为 `/admin`，导致 `/api/admin/users` 变成 `/admin/admin/users`。
*   **修复**：修改 rewrite 规则，改为仅去掉 `/api` 前缀。
    ```typescript
    rewrite: (path) => path.replace(/^\/api/, '')
    ```

### 3. API 接口路径对齐
*   **现象**：代理修复后，`/api/employee/login` 被转发为 `/employee/login`，但后端实际路径是 `/admin/employee/login`。
*   **根因**：前端 `src/api/` 下的文件（employee, category, dish 等）缺少 `/admin` 前缀，依赖之前的错误 rewrite 规则碰巧工作（或者从未工作过）。
*   **修复**：批量修改 `src/api/*.ts`，为所有管理端接口显式添加 `/admin` 前缀。
    *   `/employee/login` -> `/admin/employee/login`
    *   `/category` -> `/admin/category`
    *   (涉及文件：employee.ts, category.ts, dish.ts, setmeal.ts, order.ts, shop.ts, statistics.ts, dashboard.ts)

### 4. 响应状态码统一 (Result Code)
*   **现象**：Network 请求返回 200 且数据正常，但前端弹出 "操作失败" 且表格无数据。
*   **根因**：
    *   后端 `Result.java` 定义：`code = 0` 为成功，`code = 1` 为失败。
    *   前端 `request.ts` 及 `index.vue`：反向判断 `code === 1` 为成功。
*   **修复**：
    *   `src/utils/request.ts`：拦截器改为 `code !== 0` 时抛错。
    *   `user-management/index.vue`：所有 `res.code === 1` 改为 `res.code === 0`。

## 📊 结果验证
*   **登录**：正常跳转，Network 状态 200。
*   **用户管理**：
    *   统计卡片显示真实数据（如：总用户 8）。
    *   用户列表分页正常加载。
    *   不再弹出虚假报错。

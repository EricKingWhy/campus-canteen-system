# ECC 全局安装能力使用手册（项目实战版）

本文档用于指导你在任意项目中，系统化使用已安装的 ECC（Agents + Skills + Commands/Prompt 风格）能力。  
目标是让你从“会用”升级到“稳定高质量地用”。

## 1. 你已经具备的能力

你当前环境已具备三层能力：

1. Agents（专职角色）
- 例如：`planner`、`tdd-guide`、`code-reviewer`、`security-reviewer`、`build-error-resolver`
- 适合：分工明确、需要专业视角的任务

2. Skills（专业工作流模板）
- 例如：`tdd-workflow`、`verification-loop`、`api-design`、`backend-patterns`、`frontend-patterns`
- 适合：某类固定任务的标准化执行

3. Commands / Prompt 风格（高效指令表达）
- 你不需要记复杂命令，直接用自然语言描述“目标 + 流程 + 质量标准”
- 适合：快速发起完整链路任务

## 2. 一个项目里的完整全套流程（推荐默认）

把任何任务都按下面 7 步执行，成功率和可维护性会明显提升。

1. 需求澄清（输入）
- 明确：目标、边界、验收标准、风险点
- 推荐调用：`planner`

2. 技术方案（设计）
- 输出：模块划分、数据流、接口定义、变更范围
- 推荐调用：`planner` + `architect`（如果涉及架构）

3. 测试先行（TDD）
- 先写失败测试（RED）再写实现（GREEN）再重构（REFACTOR）
- 推荐调用：`tdd-guide` + `tdd-workflow`

4. 功能实现（编码）
- 小步提交，分阶段验证
- 推荐调用：对应语言技能（如 `backend-patterns`、`frontend-patterns`）

5. 质量评审（代码质量）
- 重点看：逻辑缺陷、回归风险、缺失测试、边界条件
- 推荐调用：`code-reviewer` + `verification-loop`

6. 安全审查（上线前）
- 重点看：输入校验、鉴权、注入风险、敏感信息泄露
- 推荐调用：`security-reviewer` + `security-review`

7. 验证与发布（收口）
- 执行：测试、构建、回归、发布说明
- 推荐调用：`build-error-resolver`（若构建失败）

## 3. 专业工作流模板（按任务类型）

### 模板 A：新功能开发（最常用）

适用场景：新增页面、接口、新业务流程。  
标准链路：`planner -> tdd-guide -> code-reviewer -> security-reviewer`

可直接用的 Prompt：

```text
按 ECC 工作流帮我完成这个新功能：{功能名}。
要求：先规划实现步骤，再按 TDD 写测试和实现，最后做代码评审和安全评审。
请输出：1) 实现计划 2) 代码修改 3) 测试结果 4) 风险与后续建议。
```

### 模板 B：修复 Bug（线上/测试环境）

适用场景：报错、异常数据、接口失败、页面错乱。  
标准链路：`tdd-guide -> build-error-resolver -> code-reviewer`

可直接用的 Prompt：

```text
帮我按 ECC 的 Bug 修复流程处理这个问题：{Bug 描述}。
要求：先定位根因，先补一个能复现问题的失败测试，再修复实现并验证通过，
最后做一次回归风险评审，列出受影响模块。
```

### 模板 C：重构与性能优化

适用场景：代码臃肿、可维护性差、慢查询、接口慢。  
标准链路：`planner -> refactor-cleaner -> code-reviewer`

可直接用的 Prompt：

```text
请对 {模块名} 做一次可维护性重构。
要求：不改变业务行为，先给出重构计划，再分批改造并逐步验证。
最后输出：改造前后对比、风险点、建议补充测试。
```

### 模板 D：安全加固（上线前必跑）

适用场景：登录、支付、上传、鉴权、后台管理。  
标准链路：`security-reviewer -> code-reviewer`

可直接用的 Prompt：

```text
对 {模块/接口} 做一次上线前安全审计。
重点检查：输入校验、SQL 注入、XSS、鉴权绕过、错误信息泄露、敏感信息管理。
请按严重级别给出问题清单和修复建议。
```

## 4. Commands / Prompt 风格最佳实践

高质量 Prompt 建议用这个结构：

```text
【目标】我要实现/修复什么
【上下文】项目模块、相关路径、当前现象
【流程】希望按哪些 Agent/Skill 顺序执行
【约束】不能破坏什么、技术栈、性能/安全要求
【输出】希望返回哪些结果（计划、代码、测试、风险）
```

推荐句式（可套用）：

1. `按 ECC 工作流处理：先 plan，再 TDD 实现，再 review。`
2. `用 tdd-guide 修复这个 bug，先写失败测试再改代码。`
3. `用 security-reviewer 审查这个接口，按严重级别输出问题。`
4. `对这个 PR 做 code-review，优先找高风险回归点和缺失测试。`

## 5. 不同环境下的 Prompt 示例（多场景可复制）

### 5.1 日常项目开发（需求实现）

```text
需求：{需求内容}
请按 ECC 专业流程执行：
1) planner 先拆解实现计划和风险
2) tdd-guide 先写失败测试再实现
3) code-reviewer 做质量审查
4) security-reviewer 做安全审查
输出完整结果和下一步建议。
```

### 5.2 项目修改 Bug（紧急修复）

```text
当前 Bug：{现象 + 报错 + 复现步骤}
请按 ECC Bug 流程处理：
先定位根因并写复现测试，再修复并跑相关测试，
最后评估回归风险并给出验证清单。
```

### 5.3 后端接口开发（Spring Boot/Node 都可用）

```text
帮我设计并实现接口：{接口名}
要求：遵循 api-design，给出请求/响应结构、错误码、分页方案，
并补充单元测试与集成测试，最后做安全检查。
```

### 5.4 前端页面开发（管理端/小程序页面）

```text
帮我实现页面：{页面名}
要求：先给组件与状态设计，再实现交互逻辑，
补充关键测试并做一次可用性与性能检查。
```

### 5.5 PR 合并前最终检查

```text
请对本次改动做上线前总检查：
1) code-reviewer 查逻辑缺陷和回归风险
2) security-reviewer 查安全问题
3) verification-loop 查测试覆盖和遗漏
最后给出可否合并结论和阻塞项。
```

## 6. 最推荐的日常用法（你可以直接照抄）

如果你只记一条，请用这条：

```text
按 ECC 标准流程帮我做这件事：先规划，再 TDD 实现，再代码评审，再安全评审，最后给我一份可执行的收尾清单。
```

这是最稳妥、最专业、最适合长期项目协作的默认工作流。

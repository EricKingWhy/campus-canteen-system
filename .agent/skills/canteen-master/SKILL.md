# Skill: Smart Canteen Thesis Expert (毕设全能专家)

## 1. Project Manifesto (项目核心宗旨)
本项目是王浩宇的毕业设计《校园食堂智能推荐与餐费分析系统》。
**最高准则**：所有代码实现必须严格对应《开题报告》中的五大核心模块。任何功能开发都不能脱离“健康引导”与“理性消费”这两个核心价值。

## 2. Technical Architecture (技术架构)
- **C端 (学生)**: UniApp + Vue3 (Script Setup) + Vite -> 微信小程序。
- **B端 (管理)**: Vue3 + Element Plus -> Web 后台。
- **后端**: Spring Boot 3.x + MyBatis Plus + MySQL 8.0。
- **安全**: Token 令牌身份认证 + 拦截器鉴权。

## 3. Core Business Logic (开题报告五大模块 - 严格执行)

### 3.1 移动端交互与点餐模块 (Interaction & Order)
-   **业务流**: 浏览 -> 规格选餐 (微辣/特辣) -> 购物车 -> 结算 -> 生成取餐码 (无配送，线下自取)。
-   **状态流转**: 已支付 -> 制作中 -> 待取餐 -> 已完成。
-   **关键细节**:
    -   **库存预警**: 必须在前端实时显示“仅剩X份”。
    -   **透明公示**: 详情页必须展示“主料成分”与“热量值”。

### 3.2 智能推荐引擎 (Smart Recommendation - 核心算法)
*代码实现时必须包含以下三层过滤逻辑：*
1.  **健康画像 (Rule-Based)**:
    -   采集身高/体重 -> 计算 BMI。
    -   规则: 偏瘦/增肌 -> 推荐高蛋白/TDEE+300；超重/减脂 -> 推荐低脂/TDEE-300。
2.  **时空上下文 (Context-Aware)**:
    -   **时间**: 早餐时段 (6:00-9:00) -> **强制过滤**重油正餐，仅推荐粥/面点/牛奶。
    -   **季节/天气**: 气温>30℃ -> 提升清淡凉菜权重。
3.  **冷启动 (Cold Start)**:
    -   若用户无画像或数据不足，使用 **“全校热销榜 Top-N”** (基于销量) 进行补全。

### 3.3 餐费与营养分析 (Data Analysis - 亮点功能)
1.  **消费预算预警**:
    -   用户设定月度限额。
    -   **三色预警逻辑**: 余额充足(绿) -> 接近限额(黄) -> 超额/不足20%(红)。
2.  **膳食结构雷达**:
    -   使用 ECharts 绘制雷达图。
    -   维度: 蛋白质 / 碳水 / 脂肪 / 膳食纤维 / 维生素。
    -   **纠偏建议**: 若肉食占比过高，必须在图表旁给出“建议增加蔬菜摄入”的文字提示。

### 3.4 菜品检索 (Retrieval)
-   支持模糊搜索 (Keyword Search)。
-   支持按“食堂档口”筛选。

### 3.5 运营决策 (Admin Dashboard)
-   **销量看板**: 展示“单品销量排行”与“档口营收统计”，识别爆款与滞销菜品。
-   **标签管理**: 管理员手动打标 (如“减脂餐”、“新品”)，作为前端推荐的数据源。

## 4. UI Design System (设计规范)
-   **风格**: 活力橙 (#FF6B00) + Bento Grid (大圆角卡片)。
-   **首页布局**:
    -   顶部: 问候语 + 天气 + 健康数据 (BMI/热量)。
    -   中部: **横向滚动**的智能推荐区 (必须显眼)。
    -   底部: 悬浮胶囊购物车 (不可遮挡 Tabbar)。

## 5. Anti-Bug & Logic Verification (防错机制)
**在生成代码前，Agent 必须进行以下自检：**
1.  **逻辑完整性**: 推荐接口是否包含了“早餐过滤”逻辑？(严禁在早上推荐麻辣烫)。
2.  **数据真实性**: 前端是否写死了数字？(必须调用后端 API，如 `getRecommendAPI`)。
3.  **空值处理**: 如果 `user.height` 为空，是否引导用户去完善信息？(不能报错)。
4.  **UI 兼容性**: 购物车条是否挡住了底部的导航栏点击区域？

当用户指令涉及“功能开发”、“逻辑修改”或“UI设计”时，**必须**先查阅本 Skill 中的“3. Core Business Logic”，确保代码实现符合开题报告要求，**严禁**生成违背业务逻辑的代码。
